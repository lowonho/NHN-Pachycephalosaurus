# 2026 ARCHIVE 게임 개발 지침

## 1. 게임 핵심 콘셉트

플레이어는 밈 기록 담당관으로서 미래의 오류로 손상된 **2026년의 기록을 복구해야만** 한다.

각 기록은 재생되는 순간부터 **20.26초 동안만 유지**되며, 제한시간 안에 해당 기록의 목표를 완성해야지만 복구된다.

게임의 핵심은 단순히 20.26초 안에 빠르게 클리어하는 것이 아니다.

플레이어가 기록에 개입할수록 하나의 물리법칙이 점점 비정상적으로 변한다.

예:

- 점프할수록 중력이 증가한다.
- 방향을 입력할수록 이동 속도가 증가한다.
- 충돌할수록 탄성이 증가한다.
- 발사할수록 반동이 증가한다.
- 이동할수록 마찰력이 감소한다.
- 특정 행동을 할수록 시야가 어두워진다.
- 회전할수록 각속도가 증가한다.

따라서 플레이어는

**“20.26초 안에 목표를 달성해야 하지만, 불필요한 행동을 반복할수록 게임이 어려워지는 구조”**

를 경험해야 한다.

---

# 2. 핵심 게임 루프

각 스테이지는 다음 순서를 따른다.

**기록 선택**

↓

**복구해야 할 장면과 목표 제시**

↓

**20.26초 카운트다운 시작**

↓

**플레이어 행동**

↓

**행동 반복에 따라 특정 물리법칙의 제약 증가**

↓

**목표 달성 또는 실패**

↓

**기록 복구 결과 표시**

↓

**2026년의 실제 밈·이슈 또는 유행 장면 공개**

---

# 3. 스테이지 설계 원칙

모든 스테이지에는 반드시 다음 네 가지가 존재해야 한다.

## 3-1. 명확한 클리어 목적

플레이어가 스테이지에 들어온 직후 무엇을 해야 하는지 바로 이해할 수 있어야 한다.

좋은 예:

- 공을 출구까지 이동시킨다.
- 물체를 목표 지점까지 운반한다.
- 캐릭터를 정상까지 이동시킨다.
- 목표물 세 개를 맞힌다.
- 지정된 위치에 정확히 착지한다.
- 구조물을 쓰러뜨리지 않고 완성한다.

피해야 할 예:

- 그냥 20.26초 동안 버티기.
- 이유 없이 물체를 계속 움직이기.
- 무엇을 성공해야 하는지 명확하지 않은 플레이.

가능하면 **행동의 결과가 화면에 보이는 목표**를 사용한다.

---

# 4. 반복 행동과 물리 제약

각 스테이지에는 하나의 대표 행동을 지정한다.

대표 행동을 반복할 때마다 하나의 물리 수치가 변화한다.

예:

### 점프

점프 횟수 증가
→ 중력 증가
→ 점프 높이 감소

### 방향 입력

새로운 방향 입력
→ 속도 또는 가속도 증가
→ 공이나 캐릭터 제어 난이도 증가

### 충돌

벽이나 물체에 충돌
→ 탄성 증가
→ 다음 충돌에서 더 강하게 튕김

### 발사

발사 횟수 증가
→ 반동 증가
→ 캐릭터나 무기의 위치가 크게 밀림

### 이동

이동 행동 반복
→ 마찰 감소
→ 정지 및 방향 전환이 어려워짐

### 회전

회전 입력 반복
→ 각속도 증가
→ 회전을 멈추기 어려워짐

### 조명 사용

행동 반복
→ 광량 감소
→ 플레이어 주변 시야가 점점 좁아짐

---

# 5. 중요한 설계 규칙

물리 제약은 단순한 숫자 증가가 아니라 **플레이 방식의 변화**를 만들어야 한다.

좋지 않은 예:

방향키 입력
→ 이동속도 5% 증가
→ 플레이어가 거의 차이를 느끼지 못함.

좋은 예:

방향키 입력 반복
→ 이동속도와 관성이 눈에 띄게 증가
→ 후반에는 작은 방향 수정도 크게 움직임.

플레이어가 반드시

**“내가 이 행동을 너무 많이 해서 이렇게 됐다.”**

라고 이해할 수 있어야 한다.

---

# 6. 20.26초 설계

모든 일반 스테이지의 제한시간은 **20.26초**로 통일한다.

20.26초는 게임의 핵심 정체성이므로 임의로 20초 또는 21초로 변경하지 않는다.

플레이어가 첫 플레이에서도 목표를 이해할 수 있도록 초기 1\~2초 안에 게임 방법을 파악할 수 있어야 한다.

스테이지 난이도는 복잡한 조작에서 발생시키지 않는다.

난이도는 주로 다음 요소에서 발생한다.

- 행동 횟수 관리
- 물리 변화 예측
- 이동 경로 선택
- 타이밍
- 최소 행동으로 목표 달성

---

# 7. 조작 원칙

한 스테이지에서 사용하는 핵심 조작은 최대한 단순하게 유지한다.

권장:

- WASD
- 방향키
- Space
- 마우스 클릭
- 드래그
- 버튼 1\~2개

한 스테이지에서 여러 기능을 동시에 학습시키지 않는다.

예:

공 미로 스테이지

**WASD 이동**

만 사용한다.

대신 방향키를 새로 입력할 때마다 공이 점점 빨라지는 방식으로 난이도를 만든다.

---

# 8. 대표 프로토타입: 가속 미로

## 목표

공을 미로의 START 지점에서 GOAL까지 이동시킨다.

## 제한시간

20.26초

## 조작

WASD 또는 방향키

## 물리 오류

새로운 방향을 입력할 때마다 공의 가속도와 최대 속도가 증가한다.

예:

1\~3회 입력
→ 정상적인 움직임

4\~7회
→ 속도 증가 체감

8\~12회
→ 제동과 방향 전환 어려움

13회 이상
→ 매우 높은 관성으로 정밀한 조작이 어려움

## 게임 의도

플레이어는 단순히 방향키를 연타하는 것이 아니라 미로를 미리 보고 최대한 적은 방향 전환으로 이동해야 한다.

즉,

**경로 판단 → 최소 입력 → 물리 변화 제어**

가 핵심 플레이가 된다.

---

# 9. 시각적 피드백

물리법칙이 변하면 반드시 시각적으로 표현한다.

예:

속도 증가

- 공 뒤에 잔상 생성
- 카메라 흔들림 증가
- 움직임 효과 증가

중력 증가

- 착지 충격 증가
- 캐릭터가 눌리는 애니메이션
- 점프 높이 감소

탄성 증가

- 충돌 효과 증가
- 튕기는 속도 증가
- 화면 흔들림

시야 감소

- 화면 가장자리 암전
- 플레이어 주변만 조명 유지

반동 증가

- 발사 시 캐릭터나 장비가 뒤로 밀림
- 카메라 반동 표현

플레이어가 UI 숫자를 읽지 않아도 현재 물리 상태를 이해할 수 있게 한다.

---

# 10. UI 원칙

화면에는 필요한 정보만 표시한다.

필수:

**20.26 타이머**

선택:

- 현재 물리 오류 상태
- 행동 누적 정도
- 목표 표시

가능하면

`속도 × 2.4`

같은 숫자보다

**속도 위험도**

또는 시각적 효과를 이용한다.

UI 자체도 후반부에는 물리 오류의 영향을 받는 연출을 사용할 수 있다.

예:

- UI가 흔들림
- 글자가 미끄러짐
- 일부 화면이 암전
- 타이머가 순간적으로 흔들림

단, 실제 플레이 정보를 읽을 수 없을 정도로 방해하지 않는다.

---

# 11. 세계관

2026년의 사건, 유행, 문화 기록을 보관하던 시스템 **2026 ARCHIVE**에 오류가 발생한다.

오류로 인해 기록 안의 물리법칙이 정상적으로 작동하지 않는다.

플레이어는 손상된 기록을 직접 재생하여 원래 장면을 복구해야 한다.

그러나 손상된 기록은 **20.26초 동안만 유지된다.**

또한 플레이어가 기록 안에 개입할수록 데이터 손상이 심해지면서 물리 오류가 증가한다.

따라서 플레이어의 목표는

**최소한의 개입으로 기록의 마지막 장면을 완성하는 것**이다.

---

# 12. 2026년 소재 활용 원칙

2026년의 밈이나 이슈는 게임 규칙보다 먼저 결정하지 않는다.

먼저 재미있는 물리 미니게임을 만든 후 해당 플레이 방식과 자연스럽게 연결되는 2026년 소재를 찾는다.

좋은 연결:

밈의 대표 행동
↔ 게임의 핵심 행동
↔ 변화하는 물리법칙

나쁜 연결:

유명한 밈이라는 이유만으로 전혀 관계없는 게임 플레이에 캐릭터나 이미지만 붙이는 것.

2026년 소재는 **스킨이 아니라 스테이지의 상황과 목적을 설명하는 역할**을 해야 한다.

---

# 13. 기록 복구 연출

스테이지 시작:

`2026 ARCHIVE`

`RECORD DAMAGED`

`RESTORE WITHIN 20.26`

목표 표시 후 바로 게임을 시작한다.

성공:

`RECORD RESTORED`

이후 해당 2026년 기록의 완성된 장면을 보여준다.

실패:

시간 초과 시

`RECORD LOST`

물리 오류가 지나치게 누적되어 플레이 불가능한 상태가 되면

`PHYSICS COLLAPSE`

를 표시할 수 있다.

실패 연출은 심각하기보다는 게임 분위기에 맞게 과장되고 코믹하게 표현한다.

---

# 14. 난이도 설계

난이도를 높이기 위해 미로 자체나 조작법을 과도하게 복잡하게 만들지 않는다.

난이도는 다음 요소를 조정한다.

- 물리값 증가량
- 행동당 페널티
- 목표까지 필요한 최소 행동 수
- 장애물 배치
- 물리 오류가 플레이에 영향을 주기 시작하는 시점

좋은 스테이지는 숙련된 플레이어가

**“이걸 4번의 입력이면 깰 수 있겠는데?”**

라고 생각하게 만든다.

---

# 15. 개발 우선순위

첫 번째 단계에서는 2026년 밈이나 아트 에셋을 넣지 않는다.

먼저 회색 박스 형태의 프로토타입을 제작한다.

우선 구현할 물리 스테이지 후보:

1. 방향 입력 → 속도 증가 → 공 미로
2. 점프 → 중력 증가 → 플랫폼 등반
3. 충돌 → 탄성 증가 → 공 골인
4. 발사 → 반동 증가 → 목표물 맞히기
5. 이동 → 마찰 감소 → 물체 운반
6. 행동 → 시야 감소 → 미로 탈출
7. 회전 → 각속도 증가 → 균형 유지

각 프로토타입을 실제로 플레이해 본 뒤 재미있는 것만 남긴다.

그 이후 2026년 소재를 대응시킨다.

---

# 16. 기술 방향

웹 기반 게임으로 제작한다.

엔진은 **Phaser 3**를 사용한다.

물리 구현은 Phaser Physics 또는 필요한 경우 Matter.js 기반으로 제작한다.

물리값은 스테이지마다 개별적으로 관리하고 공통 시스템에서 다음 값을 변경할 수 있도록 한다.

- gravity
- velocity
- acceleration
- drag
- friction
- restitution
- angularVelocity
- bounce
- lightRadius

각 스테이지는 독립적으로 제작하되 공통 인터페이스를 사용한다.

필수 공통 요소:

- 20.26초 타이머
- 게임 시작
- 성공 판정
- 실패 판정
- 재시작
- 물리 오류 단계
- 스테이지 종료
- 기록 복구 결과

---

# 17. 최종 개발 원칙

이 게임에서 가장 중요한 질문은 항상 다음과 같다.

**“플레이어가 왜 이 행동을 해야 하는가?”**

그리고

**“그 행동을 반복했을 때 어떤 물리적 문제가 생기는가?”**

두 질문에 명확하게 답할 수 없는 스테이지는 사용하지 않는다.

게임의 핵심은 복잡한 물리 시뮬레이션이 아니라,

**간단한 행동 하나가 반복될수록 예상하지 못한 물리적 결과를 만드는 재미**다.

최종적으로 플레이어가 느껴야 하는 감정은 다음과 같다.

> “빨리 움직여야 하는데, 움직일수록 더 어려워진다.”

이 긴장과 혼란을 20.26초 안에 짧고 강하게 전달하는 것을 목표로 한다.
