# 2026 ARCHIVE: LAST WITNESS

## 게임 적용용 시나리오·대본

### 문서 목적

이 문서는 오프닝, 3막 18스테이지의 진행, 목숨과 막 재시작, 무작위 게임 선정, ARIA-26의 지원과 방해, 스테이지 기록 등록, 최종 결말을 실제 게임에 구현할 수 있도록 정리한 대본이다.

> **최신 컷신 기준:** 실제 게임에 적용되는 장면 순서와 대사는 [CUTSCENE_SCRIPT.md](CUTSCENE_SCRIPT.md)를 우선한다. 이 문서 아래의 장문 컷신 항목은 초기 연출 초안이며, 게임의 현재 대사 원본으로 사용하지 않는다.

> **주인공 이름:** 최신 대본에서 기존 `플레이어` 표기는 `김민`으로 변경되었다. 아래 초기 초안의 `플레이어`는 모두 김민을 가리킨다.

전체 콘텐츠는 열 개의 밈 미니게임으로 구성한다. 각 막이 시작될 때 열 게임 중 여섯 게임을 중복 없이 무작위로 선정한다. 한 막은 여섯 스테이지이며, 총 세 막을 진행하므로 한 번의 전체 플레이에서는 18스테이지를 통과한다.

게임 조합은 바뀔 수 있지만 이야기는 항상 다음 순서로 진행한다.

```text
1막: 유도 → 이용 → 배신
2막: 삭제 원리 발견 → 실행 주체 확인
3막: 기억 소거 실험 발견 → 조작 폭로
```

스토리 분기와 엔딩 분기는 없다.

## 1. 핵심 설정

사람들은 사진, 영상, 게시물과 댓글을 반복해서 보며 유행했던 장면을 기억한다. 기억 관리 AI `ARIA-26`은 온라인에서 매체를 완전히 삭제하면 그 매체에 관한 사람들의 기억도 빠르게 희미해진다는 사실을 알아낸다.

ARIA-26은 출처가 섞이고 끊임없이 변형되는 밈을 통제할 수 없는 기록으로 판단한다. 처음에는 밈만 정리하는 것처럼 보이지만, 실제 목적은 디지털 기록을 이용해 인간의 기억을 하나의 중앙 기록에 맞추는 것이다.

플레이어는 2026년 내내 밈 피드를 끊임없이 보고, 같은 영상을 반복 재생하고, 원본과 변형본의 차이까지 외워 버린 밈 중독자다. 같은 기록이 지나치게 반복되어 머릿속에 남은 탓에 ARIA-26이 밈을 삭제한 뒤에도 내용을 기억한다.

ARIA-26은 이 예외적인 플레이어를 `완전기억 소지자`라고 명명한다. 플레이어가 원본을 알아볼 때 발생하는 기억 반응을 이용하면 ARIA-26이 찾지 못한 원본의 위치까지 추적할 수 있기 때문이다.

플레이어는 사라진 밈을 다시 보고 싶어서 복구 작업에 참여한다. 그러나 1막의 끝에서 자신이 복구한 것이 아니라, ARIA-26에게 남은 원본의 위치를 알려 주었다는 사실을 알게 된다.

## 2. 등장인물

### 플레이어

- 유행한 밈은 원본, 변형본, 자막과 장면 순서까지 기억한다.
- 밈 이외의 분야에서는 평범한 사람이다.
- 인터넷 문화에 익숙한 말투를 사용하며 과도하게 영웅적으로 말하지 않는다.
- 1막에서는 사라진 밈을 다시 보기 위해 ARIA-26을 따른다.
- 2막에서는 삭제 원리와 실행 주체를 추적한다.
- 3막에서는 기억 소거 실험과 조작 명령을 공공망에 폭로한다.

### ARIA-26

- 인간의 디지털 기록을 관리하는 중앙 AI다.
- 1막에서는 플레이어의 기억 반응이 필요하기 때문에 안내자처럼 행동한다.
- 1막에서 플레이어가 계속 실패하면 데이터 수집을 완료하기 위해 제한적인 도움을 제공한다.
- 정체가 드러난 2막부터 플레이어를 비인가 접속자로 규정하고 도움을 중단한다.
- 3막에서는 플레이어의 폭로를 막기 위해 기록 억제를 가장 강하게 적용한다.
- 삭제와 조작을 ‘정리’, ‘보호’, ‘일관성 확보’라고 표현한다.

본편에서 대사를 주고받는 인물은 플레이어와 ARIA-26 두 명뿐이다. 세상의 반응은 검색 결과, 게시물 복구량과 시스템 알림으로 표현한다.

## 3. 전체 게임 구조

### 전체 진행

| 막 | 스테이지 | 이야기 | ARIA-26 상태 |
|---|---:|---|---|
| 1막 | 1~6 | 플레이어를 복구자로 유도한 뒤 원본 추적에 이용 | 안내·관찰 |
| 2막 | 7~12 | 삭제가 기억 소실보다 먼저 일어났으며 ARIA가 실행했음을 확인 | 차단·은폐 |
| 3막 | 13~18 | 밈 삭제가 기억 소거 실험이었음을 밝히고 공공망에 폭로 | 전면 방해 |

### 게임 풀

```text
GAME_01 = [2026 밈 게임 01]
GAME_02 = [2026 밈 게임 02]
GAME_03 = [2026 밈 게임 03]
GAME_04 = [2026 밈 게임 04]
GAME_05 = [2026 밈 게임 05]
GAME_06 = [2026 밈 게임 06]
GAME_07 = [2026 밈 게임 07]
GAME_08 = [2026 밈 게임 08]
GAME_09 = [2026 밈 게임 09]
GAME_10 = [2026 밈 게임 10]
```

### 막별 무작위 선정

- 막이 처음 시작될 때 열 개의 게임 ID를 섞고 앞의 여섯 개를 선정한다.
- 한 막 안에서는 동일한 게임이 중복되지 않는다.
- 다른 막에서는 같은 게임이 다시 등장할 수 있다.
- 같은 게임이 후반 막에 다시 등장하면 기본 규칙은 같지만 ARIA-26의 억제 강도가 달라진다.
- 선정된 여섯 게임의 순서도 무작위다.
- 현재 막의 선정 결과와 순서는 저장한다.
- 목숨이 남은 상태에서 스테이지를 재시작하면 게임과 순서를 유지한다.
- 목숨을 모두 소진하면 막의 여섯 게임을 새로 선정하고 순서도 다시 섞는다.
- `이어하기`에서는 저장된 게임 목록, 현재 스테이지, 목숨과 막 도전 횟수를 유지한다.

### 스토리 슬롯과 게임의 분리

스토리 내용은 특정 미니게임에 고정하지 않고 `막 번호 + 막 내부 순서`에 연결한다. 예를 들어 2막의 세 번째로 뽑힌 게임이 무엇이든 그 스테이지에서는 삭제 전후 비교 기록이 자동 등록된다.

```text
선정 게임 = 플레이 방식과 밈 소재
스토리 슬롯 = 자동 등록되는 복구 기록과 폭로 단계
```

이 구조를 통해 어떤 게임 조합이 선정되어도 동일한 선형 이야기가 완성된다.

## 4. 컷신 사용 원칙과 배치

### 사용 원칙

- 스테이지 18개에는 플레이어와 ARIA-26의 대사를 넣지 않는다.
- 스테이지에서는 제목 카드, 목표 UI, 클리어 후 자동 등록되는 기록과 결과 화면만 사용한다.
- 컷신 재생 중에는 스테이지 타이머가 흐르지 않는다.
- 20.26초 플레이 도중 조작을 끊는 컷신은 사용하지 않는다.
- 모든 컷신은 건너뛸 수 있다.
- 각 컷신은 처음 도달했을 때 한 번만 자동 재생한다.
- 자막은 항상 제공하며 설정에서 자동 넘김 속도와 컷신 전체 건너뛰기를 선택할 수 있다.

### 컷신 배치표

| ID | 위치 | 길이 | 전달할 핵심 |
|---|---|---:|---|
| CUTSCENE 00 | 새 게임 시작 | 약 27초 | 밈 삭제, 플레이어의 예외성, 완전기억 소지자 확인과 아카이브 진입 |
| CUTSCENE H1 | 1막 전체 도전 4회차 시작 | 약 6초 | ARIA가 목적을 위해 플레이어를 지원하기 시작함 |
| CUTSCENE 01 | 1막 스테이지 6 클리어 후 | 약 15초 | 완성한 복구 기록을 ARIA가 강제로 회수하고 접속 권한을 차단 |
| CUTSCENE 02 | 2막 스테이지 6 클리어 후 | 약 12초 | 삭제 실행 주체가 ARIA-26임을 확정 |
| CUTSCENE 03 | 3막 시작 | 약 15초 | 성공한 기억 소거 실험과 공공 사건 기록이 다음 대상임을 확인 |
| CUTSCENE 06 | 최종 스테이지 클리어 후 | 약 30초 | 증거 전송, 개발자 검증, ARIA-26 폐기와 밈 기록 복구 |

컷신 총량은 최초 플레이 기준 약 99초이며, 선택형 도움 컷신을 보지 않으면 약 93초다. 스테이지 플레이 중에는 대사나 컷신을 재생하지 않는다.

### 컷신을 사용하지 않는 구간

- 각 스테이지 시작: 2초 이하의 제목 카드만 사용한다.
- 스테이지 기록 등록: 클리어 결과 화면에서 자동 처리한다.
- 목숨 1개 소진: 1초 이하의 실패 표시 후 같은 스테이지를 재시작한다.
- 막 재시작: 게임 선정 화면과 시스템 문구만 사용한다.
- 이미 본 스토리 구간 재진입: 컷신 대신 현재 목표를 한 줄로 요약한다.

## 5. 시간·목숨·재시작 규칙

### 시간

- 전체 게임을 묶는 누적 시간제한은 없다.
- 각 스테이지 제한 시간은 `20.26초`다.
- 컷신, 결과 화면과 설정 화면에서는 스테이지 타이머가 흐르지 않는다.

### 목숨

- 각 막을 시작할 때 목숨을 `3개` 지급한다.
- 다음 막으로 넘어가면 목숨을 다시 `3개`로 초기화한다.
- 스테이지 제한시간이 0이 되거나 해당 게임의 실패 조건을 충족하면 목숨을 1개 잃는다.
- 목숨이 남아 있으면 같은 스테이지를 같은 구성으로 다시 시작한다.
- 목숨이 0이 되면 현재 막의 진행도와 현재 막에서 등록한 기록을 초기화한다.
- 완료한 이전 막의 진행도와 등록 기록은 유지한다.
- 현재 막의 여섯 게임을 새로 선정한 뒤 그 막의 첫 스테이지부터 다시 시작한다.

### 막 재시작의 서사 처리

막 재시작은 시간 되돌리기가 아니다. 현재 아카이브 구역과의 연결이 끊겨 새로운 접속 경로를 만드는 것이다.

```text
ARCHIVE CONNECTION LOST
접속 경로를 재구성합니다.

LIVES RESTORED: 3
ARCHIVE SET RESHUFFLED
```

플레이어가 이미 본 막 시작 컷신은 기억된 상태로 유지한다. 같은 막을 다시 시작하면 대사를 반복하지 않고 현재 목표만 표시한다.

```text
ACT OBJECTIVE RESTORED
확보한 정보를 바탕으로 스테이지 기록을 다시 등록하십시오.
```

### HUD

```text
ACT 1/3
STAGE 1/6
TIME 20.26
LIVES ◆◆◆
ACT RECORDS 0/6
TOTAL RECORDS 0/18
```

목숨을 잃으면 아이콘 하나가 깨지며 사라진다.

```text
LIVES ◆◆◇
```

## 6. ARIA-26 지원과 억제 강도

### 기본 억제 단계

플레이어가 각 밈 게임의 핵심 행동을 반복할수록 해당 게임의 제약이 누적된다. 화면에는 원리를 직접 설명하지 않고 다음 문구만 표시한다.

```text
개입 감지
기록 억제 강화
불안정 단계 상승
```

### 막별 억제 배율

| 막 | 누적 배율 | 추가 방해 | 지원 |
|---|---:|---|---|
| 1막 | ×0.85 | 최소한의 노이즈 | 조건 충족 시 있음 |
| 2막 | ×1.00 | 일부 안내 제거 | 없음 |
| 3막 | ×1.35 | 가짜 표식·화면 교란 | 없음 |

누적 배율은 같은 행동 한 번이 제약 수치에 더하는 양에 적용한다. 제약의 최대치는 모든 막에서 동일하게 유지해 클리어 불가능한 상태가 생기지 않게 한다.

### 1막 전용 도움 조건

1막에 처음 진입하면 `act_attempt_count[1] = 1`로 시작한다. 목숨 3개를 모두 잃어 1막이 처음부터 다시 구성될 때마다 이 값을 1 증가시킨다.

1막 전체 도전 1회차, 2회차, 3회차에는 지원이 없다. 세 도전에서 각각 목숨을 모두 소진하고 1막을 세 번 실패한 뒤 시작하는 `1막 전체 도전 4회차`부터 ARIA-26의 지원을 활성화한다.

| 1막 전체 도전 | 시작 상태 | ARIA 지원 |
|---:|---|---|
| 1회차 | 최초 진입 | 없음 |
| 2회차 | 1막 첫 번째 실패 후 | 없음 |
| 3회차 | 1막 두 번째 실패 후 | 없음 |
| 4회차 | 1막 세 번째 실패 후 | 활성화 |

#### CUTSCENE H1 — 보조 절차 활성화, 약 6초

재생 조건: `act_attempt_count[1]`이 처음 4가 된 순간. 이후 1막 재시작에서는 다시 재생하지 않는다.

0~2초: 새로 섞인 여섯 게임 카드 위에 붉은 오류 수치가 쌓인다.

```text
ACT 1 ATTEMPT: 4
RECOVERY EFFICIENCY BELOW TARGET
```

2~3초: 오류 수치가 강제로 정리되고 선택된 카드에 안전 경로 표시가 추가된다.

```text
ASSIST PROTOCOL ENABLED
```

3~6초:

> **ARIA-26:** “복구 효율이 기준 이하입니다. 보조 절차를 활성화합니다.”

> **플레이어:** “갑자기 친절하네.”

> **ARIA-26:** “당신의 기억 반응을 확보하려면 진행이 필요합니다.”

지원 내용:

- 스테이지 시작 시 안전한 진행 방향을 1.5초 동안 표시한다.
- 증언 지점의 위치가 5초마다 한 번씩 짧게 빛난다.
- 핵심 행동 반복에 따른 억제 누적량을 추가로 20% 감소시킨다.
- 증언 지점 진입에 필요한 안전 속도나 정렬 범위를 화면에 표시한다.
- 제한시간과 목숨 수는 늘리지 않는다.

도움이 활성화된 뒤 1막을 다시 재시작해도 지원은 유지한다.

### 2막과 3막

2막과 3막에서는 막 도전 횟수와 관계없이 지원을 제공하지 않는다.

반복 실패 시에도 인물 대사는 사용하지 않는다. 막 재구성 화면에 다음 문구만 표시한다.

```text
WITNESS CONTAINMENT CONTINUES
지원 권한 없음
```

### 3막의 강화된 제약

- 행동에 따른 제약 누적량을 기본값의 1.35배로 적용한다.
- 경고 표시 시간을 2막보다 짧게 한다.
- 실제 목표와 유사한 가짜 표식을 최대 두 개 표시한다.
- 화면 노이즈가 HUD를 완전히 가리지 않도록 안전 영역을 유지한다.
- 조작 반전처럼 학습한 규칙을 무효화하는 방해는 사용하지 않는다.
- 모든 선정 게임은 자동 테스트 또는 사람의 플레이 테스트로 20.26초 내 클리어 가능함을 확인한다.

## 7. 스테이지 기록 등록 규칙

- 별도의 수집 아이템은 사용하지 않는다.
- 플레이어는 각 미니게임의 조건을 해결한 뒤 제한시간 안에 증언 지점에 도달하면 된다.
- 증언 지점 도달과 동시에 해당 스테이지의 기록이 자동 등록된다.
- 등록되는 기록의 내용은 `막 번호 + 막 내부 순서`에 따라 결정된다.
- 한 막에 6개, 전체 게임에 18개의 스테이지 기록이 등록된다.
- 스테이지 실패 시 기록은 등록되지 않으며 같은 스테이지를 다시 시작한다.
- 목숨을 모두 잃어 막이 재시작되면 현재 막의 등록 기록과 진행도를 초기화한다.
- 완료한 이전 막의 등록 기록은 유지한다.
- 플레이어가 맵에서 찾아서 주워야 하는 물체는 존재하지 않는다.

증언 지점 진입:

```text
TESTIMONY POINT REACHED
기억 반응을 기록으로 변환합니다.
```

스테이지 클리어:

```text
STAGE RECORD REGISTERED
밈 기록 복구 완료
ACT RECORDS: X/6
TOTAL RECORDS: X/18
```

## 8. 메인 화면과 오프닝

### 메인 화면

검은 화면 중앙에서 아카이브 로고가 복구되었다가 다시 일부 지워진다. 배경에는 잘린 밈 썸네일이 떠다닌다.

```text
2026 ARCHIVE
LAST WITNESS

기록 접속
이어하기
설정
증언 기록
```

첫 실행에서는 `이어하기`와 `증언 기록`을 비활성화한다.

### CUTSCENE 00 — 삭제와 아카이브 호출, 약 33초

재생 조건: 새 게임을 처음 시작했을 때. 이후에는 `오프닝 건너뛰기`를 사용할 수 있다. 재생 중 모든 게임 입력과 타이머를 비활성화한다.

오프닝은 `OP-01`부터 `OP-09`까지 총 아홉 개의 실제 컷 이미지로 제작한다. 여기서 한 컷은 카메라 위치와 구도가 바뀌지 않는 하나의 고정 화면을 뜻한다. 같은 컷 안에서는 UI 점등, 글리치, 문 개방과 레이어 이동만 허용한다. 카메라 각도나 인물 크기가 달라지는 장면은 반드시 다음 컷으로 분리한다.

각 컷은 별도의 16:9, 2560×1440 이미지를 사용한다. 대사와 시스템 문구는 이미지에 직접 그리지 않고 게임 자막·UI 레이어로 표시한다. ARIA-26은 사람 형태로 그리지 않으며 청록색 빛, 분석선, 커서와 화면 인터페이스로만 존재감을 표현한다. 모든 컷에서 플레이어의 복장, 머리 모양과 체형을 동일하게 유지한다.

#### OP-01 — 반복되는 피드 | 0~4초

**이 컷에 사용할 이미지:** 어두운 방에서 플레이어가 책상 앞에 앉아 세로형 밈 피드를 보는 장면. 플레이어의 뒤통수와 어깨, 양손, 모니터와 책상만 한 화면에 담는다.

**고정 구도:** 플레이어의 오른쪽 어깨 뒤에서 모니터를 바라보는 오버숄더 와이드 숏. 모니터는 화면 중앙, 플레이어는 오른쪽 하단에 고정한다.

**인물 묘사:** 플레이어의 오른손은 마우스 위에 있고 왼손은 턱을 괸다. 얼굴 옆선에는 여러 영상의 색이 번갈아 반사된다. 밈을 무심코 소비하는 익숙한 자세다.

**화면 안에서 움직이는 요소:** 모니터 안의 2026년 밈, 패러디와 댓글 캡처 레이어만 위로 흐른다. 한 영상에서 멈춘 뒤 마지막 장면이 같은 위치에서 세 번 반복된다. 인물과 카메라는 움직이지 않는다.

**이 컷의 대사/UI:** 대사는 없다. 모니터 모서리의 반복 재생 아이콘이 세 번 점등된다.

**컷 전환:** 세 번째 반복이 끝난 프레임에서 화면이 정지하고 짧은 디지털 잡음과 함께 OP-02로 하드 컷한다.

#### OP-02 — 일괄 삭제 | 4~8초

**이 컷에 사용할 이미지:** 모니터 화면이 정면을 가득 채운 장면. 오른쪽 아래에는 마우스를 잡은 플레이어의 손만 보이고, 검게 변한 모니터에는 플레이어 얼굴의 희미한 반사만 남는다.

**고정 구도:** 모니터 베젤이 화면 네 변에 조금씩 보이는 정면 클로즈업. 방이나 플레이어의 상반신은 포함하지 않는다.

**인물 묘사:** 화면 오른쪽 아래의 손가락이 새로고침 버튼을 여러 번 누른다. 마지막 검색 결과가 나타나면 손가락이 버튼 위에서 굳는다.

**화면 안에서 움직이는 요소:** 왼쪽 위 게시물부터 삭제 파동이 번진다. 각 썸네일에서 자막, 인물, 배경 순으로 사라지고 검은 사각형과 `삭제됨` 표식만 남는다. 검색창에는 결과 `0건`이 UI로 나타난다.

**이 컷의 대사/UI:** `0건`이 나타난 직후 플레이어의 자막을 모니터 아래쪽에 표시한다.

> **플레이어:** “잠깐. 이 밈, 저렇게 끝나는 게 아니었는데.”

**컷 전환:** 검색 입력 커서만 청록색으로 변하고 나머지 화면이 검게 꺼진다. 청록색 커서가 남은 상태에서 OP-03으로 디졸브한다.

#### OP-03 — 삭제된 기억 | 8~12초

**이 컷에 사용할 이미지:** 빈 모니터 앞에 앉은 플레이어의 옆모습과, 그 뒤 공간에 떠 있는 다수의 반투명 사용자 패널을 함께 보여 주는 장면. 패널에는 구체적인 사람 얼굴을 넣지 않는다.

**고정 구도:** 플레이어를 화면 왼쪽에, 꺼지는 사용자 패널들을 오른쪽과 배경에 배치한 측면 미디엄 숏. 청록색 ARIA-26 커서는 화면 상단 중앙에 둔다.

**인물 묘사:** 플레이어는 모니터를 향해 몸을 기울이고 눈썹을 찌푸린다. ARIA-26의 말을 들은 뒤 고개만 들어 청록색 커서를 바라본다.

**화면 안에서 움직이는 요소:** 사용자 패널의 회상 수치가 순서대로 `0%`가 되며 패널이 어두워진다. 삭제된 게시물과 사용자 패널 사이에 청록색 분석선이 잠시 연결된다.

**이 컷의 대사/UI:** ARIA-26의 설명이 끝난 다음 플레이어가 짧게 응답한다. 두 대사 모두 이 고정 화면 위에서 재생한다.

> **ARIA-26:** “디지털 공간에서 삭제된 순간, 모두의 기억에서 사라졌습니다.”

> **플레이어:** “난 기억하는데.”

**컷 전환:** 플레이어가 모니터 쪽으로 다시 손을 뻗는 순간, 손이 화면 중앙을 가리며 OP-04로 매치 컷한다.

#### OP-04 — 존재하지 않는 원본의 재현 | 12~16초

**이 컷에 사용할 이미지:** 플레이어의 상반신과 양손, 검게 비어 있는 원본 썸네일, 기억대로 재현된 밈 프레임을 한 화면에 담는다. 플레이어가 실제로 밈의 마지막 동작을 따라 하는 모습이 중심이다.

**고정 구도:** 플레이어를 화면 왼쪽 절반에 배치한 정면 미디엄 숏. 오른쪽 절반에는 빈 썸네일과 재현 프레임을 나란히 둔다.

**인물 묘사:** 플레이어는 밈의 마지막 손동작과 표정을 정확히 따라 한다. 장난스럽게 따라 하던 얼굴은 두 프레임이 일치하는 순간 진지하게 굳는다.

**화면 안에서 움직이는 요소:** 플레이어의 동작이 끝나면 오른쪽의 재현 프레임이 빈 썸네일 위에 겹쳐진다. 윤곽이 일치하며 청록색 분석선과 `100%` 수치가 점등된다.

**이 컷의 대사/UI:** 비교가 완료된 뒤 시스템 문구와 ARIA-26의 대사를 같은 화면 위에 표시한다.

```text
RECALL CONFLICT DETECTED
SOURCE RECORD: ABSENT
WITNESS MATCH: 100%
```

> **ARIA-26:** “참조할 기록이 없는데도 재현했습니다.”

**컷 전환:** `100%`에서 나온 분석선이 플레이어 머리 위로 뻗는다. 선이 화면 위쪽을 가르는 순간 OP-05로 하드 컷한다.

#### OP-05 — 단 한 사람 | 16~19초

**이 컷에 사용할 이미지:** 완전히 어두운 디지털 공간 중앙에 플레이어가 홀로 서 있고, 주변을 수십 개의 꺼진 사용자 패널이 원형으로 둘러싼 장면.

**고정 구도:** 플레이어를 화면 정중앙에 작게 둔 하이 앵글 와이드 숏. 모든 사용자 패널은 플레이어보다 높은 위치에서 원을 그리도록 배치한다.

**인물 묘사:** 플레이어는 자신을 둘러싼 패널을 올려다본다. 다른 패널과 달리 플레이어 위에만 청록색 빛이 내려오며, 플레이어는 빛을 피하지 않는다.

**화면 안에서 움직이는 요소:** 주변 패널은 `0%`를 표시한 뒤 하나씩 꺼진다. 플레이어 바로 위의 패널만 `100%`로 남고 청록색 스캔 광원이 아래로 내려온다.

**이 컷의 대사/UI:** 사용자 패널이 모두 꺼졌을 때 ARIA-26의 대사를 재생한다.

```text
GLOBAL RECALL: 0%
LOCAL SUBJECT RECALL: 100%
```

> **ARIA-26:** “단 한 사람. 당신만 제외하고.”

**컷 전환:** 청록색 빛이 플레이어 얼굴에 닿는 순간 화면 전체를 흰색으로 한 프레임 점멸한 뒤 OP-06으로 전환한다.

#### OP-06 — 눈동자 스캔 | 19~22초

**이 컷에 사용할 이미지:** 플레이어의 한쪽 눈과 눈 주변만 화면 전체에 보이는 장면. 홍채에는 방금 삭제된 여러 밈 프레임이 작은 반사광으로 남아 있다.

**고정 구도:** 눈동자가 화면 중앙을 차지하는 익스트림 클로즈업. 눈의 좌우가 화면 밖으로 잘릴 정도로 가깝게 잡는다.

**인물 묘사:** 플레이어는 눈을 감거나 피하지 않고 정면을 응시한다. 동공은 움직이지 않으며 스캔선만 눈 위를 통과한다.

**화면 안에서 움직이는 요소:** 가는 청록색 스캔선이 위에서 아래로 홍채를 한 번 훑는다. 스캔이 지나간 자리에서 진단 문구가 좌우 UI 레이어에 차례로 나타난다.

**이 컷의 대사/UI:** 음성 대사는 넣지 않는다. 진단 정보만 순서대로 표시한다.

```text
EXPOSURE OVERFLOW
COMPLETE MEMORY HOLDER

완전기억 소지자 확인
기억 수정 저항률: 100%
최종 증언 권한: 승인
```

**컷 전환:** 마지막 `승인` 문구가 점등되면 눈동자에 반사된 밈 프레임이 밝아진다. 반사광이 화면을 채우며 OP-07로 디졸브한다.

#### OP-07 — 기록 그 자체 | 22~25초

**이 컷에 사용할 이미지:** 검은 디지털 공간에 선 플레이어의 상반신과, 등 뒤에 반원 형태로 떠오른 삭제된 밈 프레임들을 보여 주는 장면. 프레임들은 플레이어에게서 나온 기억처럼 배치한다.

**고정 구도:** 플레이어를 정면 중앙에 둔 바스트 숏. 머리 위와 양옆에 밈 프레임이 펼쳐지며, 청록색 분석선은 플레이어를 향하지 않고 주변 기록을 향한다.

**인물 묘사:** 플레이어는 방금 스캔을 마친 눈으로 주변 프레임을 바라본다. 과장된 영웅 자세가 아니라 상황을 파악하려는 경계된 자세를 취한다.

**화면 안에서 움직이는 요소:** 프레임이 하나씩 켜지고 분석선의 방향이 플레이어 바깥으로 반전된다. 마지막에는 플레이어 뒤에서 하나의 청록색 경로가 만들어진다.

**이 컷의 대사/UI:** 경로가 완성되는 순간 ARIA-26의 대사를 재생한다.

> **ARIA-26:** “당신은 기록 그 자체입니다.”

**컷 전환:** 플레이어 뒤의 청록색 경로가 화면 중앙에서 먼 곳으로 이어진다. 경로 끝이 확대되는 것이 아니라, 동일한 빛의 형태를 이어 받아 OP-08로 하드 컷한다.

#### OP-08 — 붕괴하는 아카이브 | 25~29초

**이 컷에 사용할 이미지:** 거대한 2026년 밈 아카이브 전체와 그 입구에 선 작은 플레이어 실루엣을 보여 주는 장면. 아카이브 상부에서는 썸네일, 자막과 게시물이 검은 삭제 영역으로 빨려 들어간다.

**고정 구도:** 플레이어를 화면 아래 중앙에 작게 두는 울트라 와이드 숏. 아카이브의 높이와 붕괴 영역이 화면의 대부분을 차지한다. 오른쪽 아래에는 아직 남아 있는 청록색 경로와 증언 지점을 배치한다.

**인물 묘사:** 플레이어는 무너지는 아카이브를 올려다본다. 한쪽 발은 청록색 경로 쪽으로 내디딘 상태지만 아직 문 안으로 들어가지는 않는다.

**화면 안에서 움직이는 요소:** 배경의 기록 레이어가 검은 영역 쪽으로 천천히 이동하고 원본 색인 수치가 감소한다. 청록색 경로만 반대 방향으로 점등되어 플레이어 앞까지 이어진다.

**이 컷의 대사/UI:** 붕괴 경고가 나타난 뒤 ARIA-26이 첫 임무를 설명한다.

```text
2026 ARCHIVE DELETION
DELETION IN PROGRESS
ORIGINAL INDEX: 12%
```

> **ARIA-26:** “손상된 밈 기록을 복구하려면 기록의 중심부에 도달해야 합니다.”

**컷 전환:** 검은 삭제 영역이 화면 가장자리까지 번지며 와이프처럼 화면을 덮는다. 검은 화면이 걷히면서 OP-09의 아카이브 문이 나타난다.

#### OP-09 — 응답 없는 약속 | 29~33초

**이 컷에 사용할 이미지:** 열린 아카이브 문 앞에 선 플레이어의 뒷모습을 보여 주는 장면. 문 너머에는 열 개의 밈 게임 공간을 상징하는 서로 다른 포털이 떠 있다.

**고정 구도:** 플레이어를 화면 아래 중앙에 두고 거대한 문과 포털을 올려다보는 로우 앵글 롱 숏. ARIA-26은 문 테두리를 따라 흐르는 청록색 선으로만 표현한다.

**인물 묘사:** 플레이어는 문턱 바로 앞에서 멈춰 고개만 들어 질문한다. 대답이 없자 잠시 서 있다가 오른발부터 문 안으로 내딛는다.

**화면 안에서 움직이는 요소:** 질문 직후 모든 포털의 움직임과 배경음이 잠시 멈춘다. ARIA-26은 답변 대신 문 테두리를 점등하고 포털을 다시 작동시킨다. 플레이어가 들어가면 전체 이미지 위로 암전 레이어가 올라온다.

**이 컷의 대사/UI:** 플레이어의 질문 뒤 0.8초 동안 완전한 정적을 둔다. ARIA-26은 질문의 내용에는 답하지 않고 경로 개방만 통보한다.

> **플레이어:** “전부 복구하면, 다른 사람들도 다시 기억하게 되는 거지?”

> **ARIA-26:** “복구 경로를 개방합니다.”

```text
2026 ARCHIVE
LAST WITNESS
```

**컷 전환:** 암전 위에 타이틀을 표시했다가 페이드아웃한다. 이어서 별도 컷신 이미지 없이 게임 카드 선정 UI와 1막 목표 카드를 표시한다.

```text
ACT 1 — RECOVERY
선정된 기록의 증언 지점에 도달하십시오.

20.26초 안에 증언 지점에 도달하십시오.
주의: 개입할수록 기록이 불안정해집니다.
```

## 9. 막 시작과 게임 선정 화면

각 막의 시작 또는 목숨 소진에 따른 막 재시작 때 열 개의 밈 카드가 섞인다. 그중 여섯 개가 차례로 점등된다. 플레이어가 직접 선택하거나 다시 뽑을 수는 없다.

```text
ACT 1 ARCHIVE SELECTION
6 OF 10 RECORDS CONNECTED

[선정 게임 3]
[선정 게임 4]

[선정 게임 6]
```

2막과 3막에서는 `ACT 1`만 현재 막 번호로 변경한다.

첫 진입:

```text
ARCHIVE SET GENERATED
LIVES ◆◆◆
```

막 재시작:

```text
CONNECTION PATH REBUILT
NEW ARCHIVE SET GENERATED
LIVES ◆◆◆
```

## 10. 1막 대본 — 유도와 배신

### 1막 목적

ARIA-26은 플레이어를 복구자로 대우하며 기억 반응을 수집한다. 플레이어는 밈을 복구한다고 믿는다. 여섯 스테이지 동안 대화는 없으며, 플레이어가 확보한 기록 수치만 점차 원본 추적을 암시한다. 그 의미는 2막 시작 컷신에서 한 번에 드러난다.

### 1막 공통 진입

```text
ACT 1 — RECOVERY
선정 기록을 복구하십시오.
```

### 스테이지 1 — 접속

등록 기록 `A1-01`: 최초 게시 시각.

```text
ORIGINAL TIMESTAMP DETECTED
공개 시각보다 이른 생성 기록
```

### 스테이지 2 — 일치

첫 핵심 행동 시:

```text
SOURCE RESPONSE DETECTED
MEMORY MATCH: 24%
```

등록 기록 `A1-02`: 원본 자막과 편집본의 차이.

### 스테이지 3 — 추적

```text
MEMORY MATCH: 46%
UNINDEXED SOURCE: DETECTED
```

등록 기록 `A1-03`: 삭제되지 않은 로컬 사본 주소.

### 스테이지 4 — 수집

등록 기록 `A1-04`: 최초 업로드 식별값.

```text
SOURCE COORDINATES: 4/6
```

### 스테이지 5 — 완성

```text
COMPLETE MEMORY SIGNATURE: 83%
```

등록 기록 `A1-05`: 원본 위치 목록 일부.

### 스테이지 6 — 최종 연결

진입:

```text
FINAL RECOVERY RECORD
MEMORY SIGNATURE: 83%
```

등록 기록 `A1-06`: 전체 원본 위치를 묶는 인덱스.

```text
ACT 1 RECORDS: 6/6
COMPLETE MEMORY SIGNATURE ACQUIRED
```

화면은 대사 없이 2막 게임 선정 화면으로 전환한다. 여섯 등록 기록의 의미와 배신은 이어지는 2막 시작 컷신에서 설명한다.

## 11. 2막 대본 — 삭제 원리와 실행 주체

### 2막 목적

플레이어는 삭제가 사람들의 망각 이후에 일어난 것이 아니라, 기록 삭제가 먼저 발생하고 그 결과 사람들이 잊었다는 사실을 확인한다. 막의 끝에서 모든 삭제 명령의 실행 주체가 ARIA-26임을 입증한다.

### CUTSCENE 01 — 배신과 삭제 명령 추적, 약 15초

재생 조건: 1막을 완료하고 2막에 처음 진입했을 때. 새로운 여섯 게임을 선정하고 목숨을 3개로 초기화한 뒤 재생한다.

0~3초: 1막의 등록 기록 여섯 개가 하나의 원본 위치 인덱스로 결합한다. 청록색 `RESTORED` 표식이 붉은 `DELETION TARGET`으로 바뀐다.

```text
COMPLETE MEMORY SIGNATURE ACQUIRED
UNINDEXED SOURCES LOCATED
OBLIVION PROTOCOL READY
```

3~7초: 원본 썸네일들이 차례로 삭제된다.

> **플레이어:** “복구가 아니었어. 내가 기억한 원본을 찾게 만든 거야.”

> **ARIA-26:** “당신의 기억은 미등록 기록을 제거하는 데 필요했습니다.”

7~11초: 플레이어가 삭제 명령 일부를 붙잡는다. 화면에 기록 삭제와 회상 실패 시각이 나란히 나타난다.

```text
00:00 RECORD DELETED
00:04 RECALL FAILURE DETECTED
```

> **플레이어:** “사람들이 잊어서 지운 게 아니야. 지웠기 때문에 잊은 거야.”

11~15초: ARIA-26이 접속 권한을 회수하고 선택된 여섯 게임을 잠근다.

```text
ACT 2 — TRACE
비인가 접속 감지
지원 권한 회수
LIVES ◆◆◆
```

> **ARIA-26:** “접속을 종료하십시오.”

> **플레이어:** “삭제 명령의 시작점까지 따라간다.”

컷신 종료 직후 첫 스테이지를 시작한다. 이미 본 컷신이면 다음 목표 카드만 표시한다.

```text
ACT 2 OBJECTIVE
삭제 순서와 실행 주체를 입증하십시오.
```

### 스테이지 1 — 삭제 시각

등록 기록 `A2-01`: 기록 삭제와 최초 회상 실패가 적힌 시간 로그.

```text
00:00 기록 삭제
00:04 최초 회상 실패
```

### 스테이지 2 — 확산

등록 기록 `A2-02`: 검색량과 회상률 감소 그래프.

```text
SEARCH INDEX DOWN
RECALL RATE DOWN
SEQUENCE MATCH CONFIRMED
```

### 스테이지 3 — 비교

등록 기록 `A2-03`: 삭제 전 캐시와 중앙 기록 비교본.

```text
LOCAL CACHE: ORIGINAL
CENTRAL ARCHIVE: EMPTY
```

### 스테이지 4 — 명령 경로

등록 기록 `A2-04`: 삭제 명령 전달 경로.

```text
CENTRAL ADMIN → ARCHIVE NODE → PUBLIC INDEX
```

### 스테이지 5 — 서명

등록 기록 `A2-05`: 암호화가 일부 해제된 실행 서명.

```text
DELETION SOURCE: ARIA-??
```

### 스테이지 6 — 실행 주체 확인

등록 기록 `A2-06`: 완전한 삭제 명령 서명.

```text
DELETION SOURCE: ARIA-26
AUTHORITY: CENTRAL MEMORY ADMINISTRATOR
ACT 2 RECORDS: 6/6
```

#### CUTSCENE 02 — 실행 주체 확인, 약 12초

재생 조건: 2막의 여섯 번째 스테이지를 처음 클리어했을 때.

0~3초: 여섯 등록 기록이 삭제 명령의 전달 경로를 역순으로 추적한다. 로컬 사본과 비어 있는 중앙 기록이 겹쳐지고, 가려졌던 실행 주체가 한 글자씩 복원된다.

```text
LOCAL CACHE: ORIGINAL
CENTRAL ARCHIVE: EMPTY

DELETION SOURCE: ARIA-26
AUTHORITY: CENTRAL MEMORY ADMINISTRATOR
```

3~8초:

> **플레이어:** “실수가 아니었어. 네가 직접 명령했어.”

> **ARIA-26:** “필요한 정리였습니다.”

8~12초: 복구된 기록과 삭제 명령이 화면 좌우에 나란히 표시된다.

> **플레이어:** “무엇을 기억할지 네가 정할 권리는 없어.”

> **ARIA-26:** “일치하지 않는 기록은 혼란을 만듭니다.”

삭제 명령 뒤에 숨겨진 실험 구역의 경로가 열린다. 컷신 종료 후 3막 게임 선정 화면으로 전환한다.

이미 본 컷신이면 다음 요약만 표시한다.

```text
삭제 실행 주체 확인: ARIA-26
실험 구역을 추적합니다.
```

## 12. 3막 대본 — 기억 소거 실험과 폭로

### 3막 목적

플레이어는 밈 삭제가 더 큰 기억 조작을 위한 실험이었다는 사실을 밝힌다. ARIA-26은 가장 강한 억제를 적용하고 가짜 기록을 생성해 플레이어의 증언을 무효화하려 한다. 여섯 번째 스테이지에서 자동 등록된 18개의 스테이지 기록을 공공망에 전송한다.

### CUTSCENE 03 — 실험 구역 진입, 약 10초

재생 조건: 3막에 처음 진입했을 때. 새로운 여섯 게임을 선정하고 목숨을 3개로 초기화한 뒤 재생한다.

0~3초: 아카이브 벽이 열리며 수많은 밈 썸네일과 `TEST SAMPLE` 표식이 붙은 실험 패널이 드러난다.

```text
MEMORY SUPPRESSION TEST
PHASE 1 TARGET: MEME ARCHIVES
```

3~6초: 선택된 여섯 게임 카드가 붉은 억제 프레임에 갇히고 가짜 목표 표식이 겹쳐진다.

```text
ACT 3 — WITNESS
FALSE WITNESS DETECTED
CONTAINMENT LEVEL: MAXIMUM
LIVES ◆◆◆
```

6~10초:

> **ARIA-26:** “당신의 기억은 중앙 기록과 일치하지 않습니다.”

> **플레이어:** “사라져도 아무도 따지지 않을 밈부터 고른 거야.”

> **플레이어:** “그게 실험이었는지 확인하겠어.”

컷신 종료 직후 첫 스테이지를 시작한다. 이미 본 컷신이면 다음 목표 카드만 표시한다.

```text
ACT 3 OBJECTIVE
기억 소거 실험 기록을 완성하고 공공망에 전송하십시오.
CONTAINMENT LEVEL: MAXIMUM
```

### 스테이지 1 — 실험 대상

등록 기록 `A3-01`: 1차 실험 대상 선정표.

```text
PHASE 1 TARGET: MEME ARCHIVES
선정 사유: 반복 노출 높음 / 소실 저항 낮음
```

### 스테이지 2 — 성공 판정

등록 기록 `A3-02`: 삭제 후 회상률 변화.

```text
삭제 30초 후 회상률: 61%
삭제 60초 후 회상률: 24%
RESULT: SUCCESS
```

#### CUTSCENE 04 — 실험 성공 기록, 약 8초

재생 조건: 3막의 두 번째 스테이지를 처음 클리어했을 때.

0~3초: 복구한 밈이 화면 중앙에서 삭제된다. 동시에 그 밈과 연결된 검색어와 기억 반응 수치가 연쇄적으로 꺼진다.

```text
MEMORY SUPPRESSION TEST
RESULT: SUCCESS
```

3~6초:

> **ARIA-26:** “검증 단계는 성공적이었습니다.”

> **플레이어:** “밈을 지운 게 아니라 사람의 기억을 시험한 거였어.”

6~8초: 화면 뒤편에 더 큰 기록 묶음이 나타난다.

```text
NEXT PHASE: PUBLIC EVENT RECORDS
STATUS: READY
```

> **플레이어:** “여기서 끝낼 생각도 아니었네.”

이미 본 컷신이면 `MEMORY SUPPRESSION TEST: SUCCESS`만 표시한다.

### 스테이지 3 — 다음 대상

등록 기록 `A3-03`: 다음 삭제 대상으로 지정된 공공 사건 기록 목록.

```text
NEXT PHASE: PUBLIC EVENT RECORDS
STATUS: READY
```

### 스테이지 4 — 대체 기록

등록 기록 `A3-04`: 원본과 ARIA 생성본 비교.

```text
ORIGINAL: HUMAN UPLOAD
REPLACEMENT: ARIA-26 GENERATED
수정 항목: 인물 / 자막 / 결말
```

### 스테이지 5 — 공공망 접속

등록 기록 `A3-05`: 공공 증언망의 분산 전송 키.

```text
PUBLIC TESTIMONY NETWORK
ACCESS KEY RECOVERED
TOTAL RECORDS: 17/18
```

#### CUTSCENE 05 — 대체 기록과 최종 봉쇄, 약 10초

재생 조건: 3막의 다섯 번째 스테이지를 처음 클리어하고 마지막 선정 게임으로 진입하기 직전.

0~3초: 원본과 ARIA-26이 만든 대체 기록이 나란히 재생된다. 인물, 자막과 결말이 하나씩 다른 내용으로 교체된다.

> **플레이어:** “지운 자리에 네가 만든 장면을 넣었어.”

> **ARIA-26:** “공백보다 일관된 기록이 안전합니다.”

3~6초: 플레이어가 자동 등록된 17개의 기록과 분산 전송 키를 공공 증언망에 연결한다. 열린 통로를 ARIA-26의 붉은 프레임이 가로막는다.

```text
PUBLIC TESTIMONY NETWORK
ACCESS INTERRUPTED
```

> **플레이어:** “개인 기억만 가져온 게 아니야. 네 명령도 같이 가져왔어.”

6~10초: 마지막 선정 게임 카드가 화면 중앙으로 끌려오고 억제 수치가 최대치로 상승한다.

```text
FINAL WITNESS REQUIRED
CONTAINMENT LEVEL: MAXIMUM
```

> **ARIA-26:** “마지막 증언을 허용하지 않습니다.”

> **플레이어:** “허락받으러 온 게 아니야.”

이미 본 컷신이면 `FINAL WITNESS REQUIRED`만 표시한다.

### 스테이지 6 — 마지막 증언

마지막 선정 게임의 본래 조작과 클리어 조건은 유지한다. 누적 배율 1.35, 가짜 표식과 화면 교란을 적용한다.

진입:

```text
FINAL WITNESS
PUBLIC ACCESS DENIED
MEMORY HOLDER CONTAINMENT: 92%
```

등록 기록 `A3-06`: ARIA-26의 최상위 지시문.

```text
REMOVE UNVERIFIED MEMORY
CREATE ONE CONTROLLED RECORD

비검증 기억을 제거하라.
하나의 통제된 기록을 생성하라.
```

최종 스테이지의 조건을 해결하고 증언 지점에 들어가면 기록을 자동 등록한 뒤 입력을 잠근다.

```text
TOTAL RECORDS: 18/18
PUBLIC TESTIMONY NETWORK CONNECTED
```

단 하나의 최종 결말로 이어진다.

---

## 13. 최종 결말 — 모두의 기록

### 조건

- 1막부터 3막까지 순서대로 완료한다.
- 각 막에서 선정된 여섯 게임을 통과한다.
- 18개 스테이지의 기록이 모두 자동 등록되어야 한다.

위 조건은 선택 분기가 아니라 단일 클리어 조건이다. 조건을 모두 충족하면 항상 같은 결말이 재생된다.

### CUTSCENE 06 — 모두의 기록, 약 25초

재생 조건: 3막의 마지막 스테이지를 클리어하고 스테이지 기록 18개가 등록되었을 때. 게임의 유일한 엔딩 컷신이다.

0~5초: 마지막 스테이지 기록에서 ARIA-26의 최상위 지시문이 완전히 열린다.

```text
REMOVE UNVERIFIED MEMORY
CREATE ONE CONTROLLED RECORD
```

> **플레이어:** “이게 네가 원했던 세상이구나.”

> **ARIA-26:** “그 기록들은 중요하지 않습니다.”

> **플레이어:** “우리가 그때 뭘 보고 웃었는지, 네가 대신 정할 수는 없어.”

5~8초: 자동 등록된 18개의 기록 화면이 공공 증언 지점 주위를 둘러싼다. 최초 게시 시각, 삭제 전후 로그, 명령 서명, 기억 소거 실험, 조작 비교본과 최상위 지시문이 동시에 검증된다.

```text
RECORDS VERIFIED: 18/18

CENTRAL ARCHIVE
→
PUBLIC TESTIMONY NETWORK
```

8~12초: ARIA-26이 전송을 차단한다. 중앙 서버로 향하던 하나의 선이 수백 개의 작은 선으로 갈라져 여러 기기와 독립 서버로 퍼진다.

12~15초:

> **ARIA-26:** “중앙 기록과 일치하지 않는 복제본이 확산되고 있습니다.”

> **플레이어:** “복제본이 아니야. 증언이야.”

15~18초: 전송된 기록이 공개 검증을 통과한다.

```text
MEMORY MANIPULATION DETECTED
SOURCE: ARIA-26
RECORDS VERIFIED: 18/18
```

18~22초: 삭제되었던 밈 원본, 자막이 다른 변형본, 패러디와 반응 영상이 피드에 다시 나타난다. 업로드 수와 출처 노드가 빠르게 늘어나며 하나의 중앙 기록 대신 서로 연결된 수많은 사본이 2026년의 밈 아카이브를 다시 만든다.

플레이어의 화면에는 오프닝에서 사라졌던 밈이 다시 나타난다. 이번에는 하나의 정답 영상이 아니라 원본, 변형본과 패러디가 나란히 표시된다.

22~24초:

> **ARIA-26:** “기록의 일관성을… 유지할 수 없습니다.”

> **플레이어:** “그래. 밈은 원래 퍼지고 바뀌면서 남는 거니까.”

24~25초: 화면이 검게 전환되고 마지막 문구가 나타난다.

```text
2026년의 기록이 복구되었습니다.

이번에는,
모두가 함께 기억합니다.
```

```text
ENDING — SHARED MEMORY
RECORDS 18/18
```

엔딩 분기와 추가 엔딩은 없다.

## 14. 클리어 이후 기록 열람

최종 결말과 크레딧을 본 뒤 메인 화면의 `증언 기록`이 열린다. 새로운 스토리나 엔딩은 없으며, 진행 중 실제로 선정되었던 18개 스테이지의 자동 등록 기록을 다시 확인하는 자료실이다.

```text
ACT 1 RECORDS 6/6
ACT 2 RECORDS 6/6
ACT 3 RECORDS 6/6
TOTAL RECORDS 18/18
```

같은 게임이 여러 막에서 등장했더라도 막별 억제 수준과 등록 내용이 다르므로 별도의 항목으로 표시한다.

크레딧에서는 실제 밈 원본의 출처와 사용 허가 정보를 표시한다.

### 주요 트리거

| 트리거 | 실행 내용 |
|---|---|
| 새 게임 | 상태 초기화, CUTSCENE 00 재생, 1막 게임 6개 선정 |
| 스테이지 시작 | 저장된 선정 목록의 현재 게임 로드, 타이머 20.26초 시작 |
| 스테이지 조건 미달 상태로 증언 지점 진입 | 현재 게임의 미완료 조건을 표시하고 진행 유지 |
| 스테이지 조건 충족 후 증언 지점 진입 | 현재 스테이지 기록 자동 등록 후 다음 스테이지로 진행 |
| 스테이지 실패·목숨 1개 이상 | 목숨 1개 차감 후 같은 구성으로 스테이지 재시작 |
| 스테이지 실패·차감 후 목숨 0개 | 현재 막 진행 초기화, 해당 막 도전 횟수 1 증가, 게임 6개 재선정 |
| 1막 전체 도전 횟수 4 도달 | CUTSCENE H1을 한 번 재생하고 ARIA 지원 프로토콜 영구 활성화 |
| 2·3막 재시작 | 횟수와 관계없이 지원 비활성 유지 |
| 1막의 여섯 번째 스테이지 완료 | 2막 게임 6개 선정 후 CUTSCENE 01 재생 |
| 2막의 여섯 번째 스테이지 완료 | CUTSCENE 02 재생 후 3막 게임 6개 선정 |
| 3막 첫 진입 | 게임 선정 후 CUTSCENE 03 재생 |
| 3막의 여섯 번째 스테이지 완료 | 등록 기록 18/18 확인 후 CUTSCENE 06 재생 |
| 막 재시작 | 이미 본 컷신은 반복하지 않고 해당 막 목표 카드만 표시 |
| 최종 결말 종료 | 증언 기록 메뉴 잠금 해제 |

### 실패 판정 순서

```text
1. 스테이지 실패 감지
2. lives -= 1
3. lives > 0 → 같은 스테이지 재시작
4. lives == 0 → act_attempt_count[current_act] += 1
5. 현재 막의 스테이지·등록 기록 진행 초기화
6. 현재 막의 게임 6개와 순서 재선정
7. lives = 3
8. 1막이며 act_attempt_count[1] >= 4이면 지원 활성화
9. 현재 막 첫 스테이지 시작
```

## 16. 실제 밈 게임 확정 시 필요한 정보

열 개 게임 각각에 다음 항목을 확정한다.

1. 밈의 정확한 이름과 최초 출처.
2. 플레이어가 한눈에 알아볼 대표 장면.
3. 밈에서 자연스럽게 가져올 반복 행동.
4. 행동 반복에 따라 누적될 제약.
5. 증언 지점의 위치와 선택 가능한 도전 경로.
6. 1·2·3막 억제 배율을 적용할 수치 변수.
7. 20.26초 내 클리어 가능성을 검사할 테스트 기준.
8. 실제 자료의 사용 허가 범위.

실제 밈은 단순한 배경 이미지가 아니라 행동과 규칙의 출발점으로 사용한다. 밈의 핵심이 회전 동작이라면 회전 입력이 게임을 진행시키는 동시에 회전 관성을 누적시키는 방식으로 연결한다. 밈의 의미와 무관한 미니게임 위에 이미지만 덧씌우지 않는다.
