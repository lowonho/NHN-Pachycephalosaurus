# E4 왕사남 호랑이 추격

## 결과 컷
- `e4-outcome-fail.png`: 호랑이에게 잡힌 직후 2초간 표시하고, 이후 재도전 결과창을 엽니다.
- `e4-outcome-success.png`: 왕에게 도착한 직후 2초간 표시하고, 일반 스토리에서는 다음 스테이지로 자동 진행합니다.
- QA 모드에서는 성공 컷 뒤에도 기존 QA 결과창을 열어 검수 목록으로 돌아갈 수 있게 합니다.

## 유지한 게임 규칙
- 19×7 랜덤 미로, 7회전 주 경로, 통로 66×90px, 벽 28px. 전체 874×382px를 한 화면 중앙에 표시합니다.
- 시작 속도 240px/s, 새 방향 입력마다 +100, 최고속도 800px/s, 제동 2400px/s², 제한시간 20.26초와 WASD/방향키 조작을 유지합니다.
- 벽 충돌은 기존 기본 1초 차감입니다. 호랑이 몸통에 닿으면 `finish(false)`로 실패하고, 왕의 목표 영역 반경 16px에 도착하면 `finish(true)`로 성공합니다.
- 호랑이는 시작점에서 22px 뒤에 배치하고 3초 동안 대기합니다. 이후 4초간 200px/s로 어슬렁거리다가, 시작 7초부터 440px/s로 달립니다. 플레이어 속도와 무관하게 이동 속도는 두 종류뿐입니다. `chase`의 `delay`, `walkDuration`, `walkSpeed`, `runSpeed`에서 조절합니다.
- 통로를 탐색하고 노드 사이를 끝까지 이동한 뒤 경로를 갱신합니다. 몸통 중심 반지름 10px로 벽과 플레이어를 검사하며 꼬리는 판정에 넣지 않습니다.

## 배치·크기·모션
- 네 건물은 기존 벽 내부의 28×28 슬롯에 원본 비율로 배치합니다. 종류는 맵 생성 시 좌표 해시로 고정하고, 게임 RNG와 충돌 맵은 바꾸지 않습니다.
- `inn`은 2×1, `longHouse`는 1×2 슬롯용입니다. 해당 슬롯이 모두 기존 벽이고 비어 있을 때만 배치합니다. 현재 긴 건물 파일이 없어 실제 맵에는 작은 건물 4종만 표시합니다.
- 바닥은 코드로 그려 반복 이미지 경계가 없습니다. 컨셉 이미지를 배경에 깔지 않으며 출발/목표의 원 표시는 제거했습니다.
- 64px 기준 크기를 현재 통로 66px에 비례 적용합니다. 인물·왕 긴 쪽 약 45.4px, 호랑이는 꼬리 포함 66px입니다.
- 왕은 0.8초마다 2프레임을 교대하며 기존 목표에 고정됩니다.
- 호랑이는 1→2→3→2로 반복합니다. 실제 이동 거리에 따라 재생 속도를 조절하고 위쪽 원본에 맞춰 `atan2(dy,dx)+PI/2`로 몸통 중심 회전합니다.
- 엄흥도는 실제 앞·뒤 시트를 `playerDown`, `playerUp`으로 연결했습니다. 좌우 전용 시트는 없으므로 위에서 본 뒷모습을 몸통 기준 ±90° 회전합니다. 추후 `playerRight`와 프레임 메타데이터를 연결하면 오른쪽 시트를 좌우 반전해 사용합니다. 모든 방향에서 같은 갈색 바지 디자인입니다.
- 엄흥도는 1→2→3→2 반복, 실제 이동 속도 기반 재생, 정지 시 1번 자세를 사용합니다. 완전 투명이 아닌 가장자리 픽셀까지 포함해 프레임을 자르고, 공통 기준 길이 582px 및 몸통 원점으로 프레임·방향 변경 시 배율과 위치를 유지합니다.

## 아직 없는 파일
- 엄흥도 좌우 전용 시트는 없으며, 현재 제공된 앞·뒤 시트로 네 방향을 표현합니다.
- `originals/player.png`는 이전 체크무늬가 그림에 포함된 단일 이미지여서 모션 시트로 사용하지 않습니다.
- 주막·긴 건물 원본도 없습니다. `inn`/`longHouse` 연결부만 준비했고 건물 두 슬롯 안전 배치는 테스트용 이미지로 검증합니다.
